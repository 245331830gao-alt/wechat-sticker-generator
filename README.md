# 微信表情包生成器

**Wechat Sticker Generator** 是一个给 AI 助手使用的 Skill：上传一张人物、宠物或卡通形象图，用中文选择动态或静态，生成一整套表情专辑素材及投稿资料。

- 默认16款动态；可选择静态及8、12、16、20、24款。
- 保留参考形象的辨识度，按主题设计表情、手势和中文文案。
- 动态使用真实绘制的动作关键帧；捂脸有抬手过程，吐舌有张嘴和伸舌过程。
- 名称默认不带品牌；支持可选中文前缀。
- 自动排版、编码、检查尺寸/体积/透明背景、生成说明，并打包ZIP。
- 检查重复姿态、静帧伪GIF、主图/缩略图对应、文件SHA256、ZIP完整性与内容一致性。

## 在AI助手中使用

将本目录作为 `wechat-sticker-generator` 技能导入支持自定义Skill的宿主。Codex可以放入其用户技能目录；其他宿主按各自的导入方式安装。上传一张图后，例如：

> 使用 $wechat-sticker-generator，以这张图为主角，制作16款动态表情，主题为犀利吐槽，准备完整微信投稿资料。

> 使用 $wechat-sticker-generator，生成20款静态表情，主题为打工人，名字不加品牌前缀。

> 用这张图制作16款动态表情，温暖治愈风格，专辑名称前加“星星”。

只上传图片时，默认16款动态、日常吐槽。生成动态和静态两版时分别出包，主图不混装。

## 能力依赖与限制

本项目由**技能工作流**和**本地编码脚本**组成。实际图像生成、去背景及关键帧绘制需要宿主提供可用的图像/视频模型工具；本仓库不包含模型、服务密钥或独立生图API。不能仅运行Python脚本，就让任意照片自动长出新的动作。缺少生图能力时，助手须明确说明，不能用原图加字凑整套。

本地脚本需要Python 3.10+、Pillow，以及有使用许可的中文字体。默认动图通常采用4–12个绘制姿态；姿态切换不等于原动画连续高帧率画面。GIF不含声音。

## 脚本工作流

```bash
python -m pip install -r requirements.txt
python scripts/stickers.py plan --reference /path/reference.png --output work/制作计划.json --mode dynamic --count 16 --title 吐槽日常
```

AI助手查看参考图、生成不同姿态，并填写制作计划中的角色介绍、场景、动作及 `frames`。具体字段见 [references/manifest.md](references/manifest.md)。

```bash
python scripts/stickers.py build --manifest work/制作计划.json --output work/第一期/投稿成品 --font /path/chinese-font.otf
python scripts/stickers.py validate --directory work/第一期/投稿成品
```

可选命名前缀：在 `plan` 中加入 `--prefix 星星`，或在JSON中设定 `name_prefix`。输出目录须为空；构建失败会清理暂存内容，不留下半套最终资料。修订时请使用新的输出目录。

## 交付内容

| 文件 | 用途 |
| --- | --- |
| 主图/ | 动态GIF或静态PNG，默认240×240 |
| 缩略图/ | 与主图按编号对应的120×120 PNG |
| 专辑素材/ | 封面、聊天图标、详情页横幅 |
| 赞赏素材/ | 引导图和致谢图候选素材 |
| 表情清单.tsv | 名称、含义词建议、使用场景、动作及文件对应 |
| 投稿文案.txt | 专辑介绍、角色介绍、署名与权属字段、赞赏拟稿 |
| 使用说明.txt、完整使用说明.html | 完整使用方法与可查看全套的预览页 |
| 素材参数清单.tsv、检查报告.json | 实际参数与检查记录 |
| 投稿准备清单.txt | 提交步骤和待补项 |
| 浅底总览.jpg、深底总览.jpg | 深浅背景下的静态效果对照 |
| 专辑名投稿资料.zip | 全套打包文件，生成在成品目录的上一级 |

## 微信投稿

[微信表情开放平台](https://sticker.weixin.qq.com/) 的当前后台提示是最终核对依据。仓库配置仅是保守制作目标，不是持续有效的官方上限或审核保证。官方正文无法读取时仍完成素材，但明确记录“待平台复核”。

文件检查、人工目检、平台规范核对、权属证明和平台审核是不同状态。人脸、手、字幕、图集跨格残片、动作语义及节奏仍要逐张检查；不能因为像素检查通过就宣称动作一定正确。

实际作者、权利人、肖像或角色授权材料需要据实提供。本项目不会伪造授权、版权登记、账号或审核回执，也不会自动上传送审或公开发布。
